## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → build | Third-party package (driver.js) enters the app supply chain at install time |
| localStorage → app | The `tourSeen` flag is attacker/user-editable client state |
| translations/step copy → DOM | Tour copy is rendered by driver.js into `document.body` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SC | Tampering | `npm install driver.js` (supply chain) | mitigate | Pin explicit `^1.6.0` in package.json; RESEARCH.md Package Legitimacy Audit already ran slopcheck 0.6.1 → [OK], verified MIT license, no postinstall script, ~1.1M weekly downloads, maintainer continuity confirmed. No unverified/[ASSUMED]/[SUS] packages introduced, so no blocking human checkpoint required. |
| T-01-01 | Tampering | `tourSeen` localStorage flag | accept | Tampering only forces the tour to re-show or not-show for that browser; no privilege, no data exposure, no backend. Harmless by design (client-only, per-browser cosmetic state). |
| T-01-02 | Information Disclosure / Injection | Tour step copy rendered via driver.js | mitigate | Step title/description are authored as plain text constants (no interpolation of user/URL input). Copy rule forbids embedded HTML beyond at most a single static `<strong>` — no `dangerouslySetInnerHTML` of dynamic data, so no injection vector via translations. |
</threat_model>
