| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | localStorage 'language' value read by the D-03 effect / languageAtom | mitigate | `resolveTourLocale` only ever returns a value from the closed `SUPPORTED_LOCALES` set (derived from `translations` keys); an arbitrary/tampered stored value flows through `translations[locale]?.tour?.[key] ?? translations.en.tour[key]` in getTourString, so an unknown key yields the safe English fallback rather than `undefined`/injection. No dynamic property write from the stored value. |
| T-03-02 | Tampering/EoP | tour copy rendered into `.driver-popover` title/description | accept | driver.js 1.6.0 sets title/description via `innerText` (confirmed in RESEARCH.md §Security Domain, driver.js.mjs:410), not innerHTML; all 30 locale strings are static author content (D-06), plain text, no embedded HTML per the Copywriting Contract. No user-supplied string reaches the popover. |
| T-03-03 | Tampering | prototype pollution via `translations[userInput]` | accept | `locale`/`language` are always drawn from the `Language` union (30 compile-time literals) via `languageAtom`; never raw unvalidated input. TypeScript + SUPPORTED_LOCALES constrain the domain. |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages this phase (RESEARCH.md §Package Legitimacy Audit: N/A). No install step; nothing to slopcheck. |
